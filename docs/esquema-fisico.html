Lo que agregué que no estaba en el papel

  1. GitHub Actions como parte de GitHub: el CI (suite completa + pip-audit) y el colector de métricas de Render. Sin esto el eje GitHub ↔ Grafana no se entiende.
  2. Georef + Nominatim y Web Push: dos servicios externos más que la app llama desde el servidor, sin claves el primero y con VAPID el segundo.
  3. ARCA como paso manual del afiliado: por decisión no se integra (el captcha lo resuelve la persona y sube la captura).
  4. El equipo (SDN, ARS) como actor aparte de los usuarios finales: son quienes desarrollan, operan y reciben las alertas.
  5. Dentro de cada entorno, lo que lo hace funcionar: Pre-Deploy con Alembic, /healthz como Health Check, y en Pruebas los techos del engine y la solapa Planes.
  6. Vencimientos que ya conocemos: token del disparador (2026-10-18), tokens de Grafana de la app (2027-09-19). Están en las fichas de Grafana y GitHub.

Preguntas para afinar la v2

  1. ¿Qué dice debajo de "API Render"? Leo "PORTA" o "PUERTA".
  2. ¿"ADM" es /entornos, o es el panel de administración del sindicato y "SIND" otra cosa?
  3. Telegram: ¿lo querés como canal real de alertas (Grafana Cloud lo soporta con un bot) o era una idea?
  4. Cloudflare: ¿lo damos por decidido para el perímetro, o hay que evaluar alternativas antes de comprar el dominio?
  5. Costos: ¿el plan actual de cada servicio web y de cada Postgres en Render? Es el dato que falta para que la pantalla muestre gasto mensual.
